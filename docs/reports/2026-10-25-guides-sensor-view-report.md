# 出口の紹介ページ（10 言語）・歩数で進み具合・後ろからの視点

- 日時: 2026-10-25
- ブランチ: claude/guides-sensor-view（claude/amenities の上）

## やったこと

### 出口ごとの紹介ページ（検索から来る観光客向け）

- `guide/<言語>/exit/<番号>/`（例: `/guide/ko/exit/d21/`）に、161 出口 × 10 言語 = 1,610 ページと、言語ごとの出口一覧 10 ページ（合計 1,620、約 8MB）
- 中身: 出口がつながる地下街と階、地上の近くの建物、地下の近くの店（60m 以内）、「この出口まで地下の道を案内する」（アプリをその出口と言語で開く: `?to=…&n=…&hl=ko`）、ほかの言語へのリンク（hreflang）、canonical、構造化データ（Place）、OSM の出典
- 作り方: `src/app/guidePages.ts`（型チェック・テストあり）を、アプリのビルドのあとに `vite.guides.config.ts` で Node 用にまとめて `scripts/guides/writeGuides.ts` が `dist/guide/` に書き出し、サイトマップ（1,621 URL）に足す（`npm run build` の続き）
- Service Worker には入れない（`globIgnores`）。アプリを入れた人が紹介ページを開いても、アプリにすり替えない（`navigateFallbackDenylist`）
- アプリは URL の `?hl=` の言語で開く

### 歩数で進み具合（使う人だけ）

- 道案内の「歩いた分を数える（動きのセンサー）」を押すと、端末の加速度から歩数を数え（`StepDetector`: なめらかにした加速度の山を 1 歩、近すぎる山は数えない）、「この区間 約 80m / 100m」と出す。区間の 8 割ほど歩いたら「そろそろ次の案内です。目印が見えたら『次へ』」
- 自動では進めない（研究では、目印で確かめ直すのが精度を大きく上げる）。iOS はボタンを押したときに許可を求める。使えない・断られたときは「次へ」で進む
- テスト: 1 秒 2 歩の揺れで 10 秒 18〜21 歩、静止では 0 歩

### 後ろからの視点

- 一人称の画面の左上（小さな地図の下）に「後ろから見る ⇄ 目の高さで見る」。後ろからは、目の高さ 2.8m・地平線を上げて床を広く見せ、少し前に自分の印（進む向きの矢印）を置く
- 研究（Burigat ほか 2017、N=78）では、後ろ・上からの視点の方が一人称より向きをつかむのが早く負担が少ない。選んだ視点は端末に覚える

## 見送り
